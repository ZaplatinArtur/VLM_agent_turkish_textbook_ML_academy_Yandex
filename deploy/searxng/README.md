# SearXNG для B1

GPU не нужен — инстанс поднимается где угодно, хоть на ноутбуке.

```bash
cd deploy/searxng
SEARXNG_SECRET=$(openssl rand -hex 32) docker compose up -d
python ../../scripts/probe_searxng.py --url http://localhost:8080
```

В `.env` прогона: `MLA_SEARXNG_URL=http://<хост>:8080`.

## Проверять перед каждым прогоном

`probe_searxng.py` берёт из логов реальные запросы модели, которые в прошлый раз
вернули пустоту, и прогоняет их через инстанс. Возвращает 1, если пустых больше
20% — это гейт: при непройденном гейте прогон измерит неисправность бэкенда, а
не поведение модели. Ровно это и случилось с `b1_deep` (71% пустых).

## Что важно знать про движки

Здоровье инстанса — величина переменная, и её нельзя настроить один раз.
Измерено на живой пробе 05.08:

| Пауза между запросами | Пустых из 25 |
|---|---|
| холодный инстанс, 0.5 с | 4% |
| он же сразу следом, 0.5 с | 64% |
| после отдыха, 6 с | 20% |

DuckDuckGo и Startpage отдают капчу почти сразу, Brave — таймаутит и
восстанавливается, Google CSE держится дольше всех, но тоже уходит. Отсюда две
вещи в клиенте (`mla_baseline/tools/searx.py`): пауза между запросами
(`MLA_SEARX_MIN_INTERVAL_S`, по умолчанию 3 с) и кэш повторов — в прогонах 26%
запросов повторялись.

Важно: отвалившиеся движки сами по себе не означают поломку. На живой пробе
brave и startpage лежали на всех 25 запросах, и при этом 24 запроса вернули
результаты — выдачу давали остальные. Поэтому клиент считает бэкенд сломанным
только тогда, когда пустота идёт на инстансе, который давно ничего не отдавал.

## Если пустых много

1. Дать инстансу отлежаться 10–15 минут — баны движков временные.
2. Увеличить `MLA_SEARX_MIN_INTERVAL_S`.
3. Добавить движков в `settings.yml` (у образа их 274, включена лишь часть).
4. Проверить, что `json` есть в `search.formats` — без него API молча пуст.

Остановить: `docker compose -f deploy/searxng/docker-compose.yml down`.

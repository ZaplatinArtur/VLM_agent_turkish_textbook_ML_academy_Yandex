Корпус — единственный невосстановимый артефакт: пересбор это сутки скрейпинга
(`scripts/scrape_odevjet_text.py`). Целостность проверена после скачивания:
распаковывается без ошибок, 42 553 записи, совпадает с серверным размером.

Не забиралось, потому что выводится из корпуса за минуты:
`data/corpus/chunks.jsonl` (200 МБ), `data/corpus/pages.jsonl` (170 МБ),
`data/bm25.sqlite` (396 МБ). Восстановление:

```
vlm-judge prepare-corpus --input odevjet_corpus.jsonl --out-dir data/corpus
vlm-judge build-bm25 --chunks data/corpus/chunks.jsonl --db data/bm25.sqlite
python -m vlm_judge.retrieval_server --db data/bm25.sqlite --port 8770
```

## Чистка корпуса (сделана 2026-08-03)

`report.json` показывал `low_information_pages: 14435` — конвейер признал
малоинформативными 34% страниц. При этом в прогонах agent_rag 16% выдач всё
равно возвращали верхним чанком навигационный шаблон ÖdevJet: подавление
работало по странице целиком, а мусор сидел построчно внутри нормальных
страниц.

Фильтр построен по фактическим данным корпуса: перечисленные строки
(`Ders Kitabı`, `Öğrenci Çözümleri`, `Çözümü Değerlendir`, кнопки, виджет
реакций, `Mehmet Ali Taş`) встречаются ровно по одному разу на каждой из
42 553 страниц — это интерфейс, а не текст. Сопоставление строгое, по всей
строке: подстрокой резать нельзя, `Çözüm` и `Sonuç` есть внутри решений.
Списки — в `scripts/odevjet_boilerplate.py`, общем со скрейпером.

```
python scripts/clean_corpus.py odevjet_corpus.jsonl.gz odevjet_corpus.clean.jsonl.gz --min-chars=200
```

Результат: убрано 665 324 строки (21.8% корпуса), шаблонных строк осталось 0,
маркеры настоящих решений (`Adım 1:`, `Sonuç:`, `Çözüm:`, `Soru 1:`) не
пострадали — 144 740 до и после. Выяснилось, что 15 333 страницы (36%) под
навигацией не содержали ничего: они отсечены по `--min-chars=200`, осталось
**27 220 страниц с реальным содержанием**.

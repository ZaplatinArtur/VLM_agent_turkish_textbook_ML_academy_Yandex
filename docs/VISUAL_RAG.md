# Визуальный ретрив: от клона до прогона

ColQwen2.5 ищет **текстовым запросом по изображениям страниц** учебников
(семейство ColPali, поздним взаимодействием MaxSim). Это не поиск картинки по
картинке: запрос — обычная строка, документ — картинка страницы.

Подключён как **второй бэкенд той же тулы** `search_textbooks`. Схема тулы и
цикл агента одинаковы в обоих режимах, поэтому «текст против визуала» — это
один переключатель, а не разные пайплайны.

## Что нужно иметь

| | где взять | размер |
|---|---|---|
| адаптер `models/colqwen25_turkish` | `models.zip` от d.bykov | 240 МБ |
| базовая модель `vidore/colqwen2.5-base` | Hugging Face | ~2 ГБ |
| индекс `colqwen25_turkish_full_index` | у d.bykov, собран на V100 | ~14 ГБ |
| картинки страниц | корпус `data/visual_retrive/books` | — |

Индекс в git не лежит и лежать не будет. Ветка ждёт его по пути из
`MLA_VISUAL_INDEX_DIR`.

## Установка

```bash
git checkout feature/visual-rag
pip install -e ".[visual,dev]"
```

`colpali-engine` импортируется лениво, поэтому без extra `visual` всё
установится и запустится, а упадёт только на первом обращении к поиску —
посреди прогона. Ставьте сразу.

## Калибровка порога — обязательный шаг

Счёт MaxSim зависит от индекса и не лежит в [0, 1], поэтому дефолтный порог
детектора (0.57) к нему неприменим, и визуальный бэкенд без явного порога не
создаётся вовсе.

```bash
export MLA_VISUAL_INDEX_DIR=/путь/к/colqwen25_turkish_full_index
python -m retrieve.evaluation.calibrate_visual
```

Гоняет свои и чужие запросы из `data/eval/`, берёт top-1 каждого и ищет
порог, который их разделяет, — тот же метод, которым сняты пороги текстовых
профилей. Печатает готовую строку `MLA_VISUAL_MIN_SCORE=...` и пишет отчёт в
`configs/visual_threshold.json`.

### Порог у ColQwen не разделяет — проверено

Замер 16 августа 2026 на индексе `colqwen25_turkish_full_index` (53 329
страниц): `separable: false`, `out_domain_leaked: 1.0`. Медиана своих запросов
0.7725, чужих — 0.7754, при том что «чужие» это вопросы про Docker, Kubernetes
и React, а свои — про площадь прямоугольника и сумму углов треугольника.

Сперва счёт зависел от длины запроса (MaxSim суммирует по токенам, а чужие
запросы оказались в полтора раза длиннее). Нормировка на число токенов
починила шкалу, но не разделимость: распределения совпали.

**Вывод: у late-interaction вся различающая сила в порядке выдачи, а не в
величине счёта.** Абсолютным порогом её не поймать. На практике это значит,
что детектор бесполезного поиска в визуальном режиме инертен — он пропускает
всё, включая случаи, когда релевантной страницы нет. Текстовый профиль этим не
страдает: там порог 0.50 по шкале кросс-энкодера снят и разделяет.

Асимметрию надо указывать в отчётах: визуальная ветка не умеет сказать
«не нашёл». Сам отчёт калибровки —
`reports/visual_threshold_colqwen25_20260816.json`.

## Предполётная проверка

```bash
python -m mla_baseline.visual_preflight
```

Проверяет по пунктам: включён ли бэкенд, стоит ли `colpali-engine`, задан ли
порог, лежат ли все пять файлов индекса, существует ли адаптер, записанный в
`meta.json` индекса, задан ли промпт-профиль. Если конфигурация сошлась —
дёргает настоящий пробный запрос.

Ненулевой код возврата означает «запускать нельзя», и каждая строка говорит,
что чинить. Два часа карты дороже двух секунд этой проверки.

## Запуск

### Воркер и карта 1:1 — сервис не нужен

```bash
export MLA_RETRIEVAL_BACKEND=visual
export MLA_VISUAL_TRANSPORT=inprocess
export MLA_VISUAL_INDEX_DIR=/путь/к/индексу
export MLA_VISUAL_MIN_SCORE=<из калибровки>
export MLA_VISUAL_IMAGE_TOP_N=1
export MLA_PROMPT_VERSION=v2_cot_text_rag_v1

python -m mla_baseline.runner --condition agent_rag --tasks data/eval/validation.jsonl
```

Индекс грузится в процесс воркера через `mmap`, целиком в память 14 ГБ не
читаются.

### Воркеров больше, чем карт — поднимается сервис

```bash
CUDA_VISIBLE_DEVICES=2 ./scripts/serve_visual_search.sh 8780
# ждать 200 на http://localhost:8780/health

export MLA_VISUAL_TRANSPORT=http
export MLA_VISUAL_URL=http://localhost:8780
```

Тогда модель и индекс живут в одном экземпляре на карту, а воркеры ходят по
сети. Сервис отдаёт картинки страниц base64, поэтому агенту не нужен доступ
к файлам корпуса и он может стоять на другой машине.

### Обе ветки на один запрос — `hybrid`

```bash
export MLA_RETRIEVAL_BACKEND=hybrid
# плюс всё то же, что для visual: индекс, порог, транспорт
```

Запрос уходит в текстовый и визуальный ретрив одновременно, выдачи сливаются
по рангам (RRF, `rrf_k=60`), в трассе у каждого хита стоит `found_by` — какая
ветка его нашла. Слабую выдачу ветка в слияние не отдаёт, а падение одной
ветки не роняет запрос: вторая ещё может ответить.

Слияние по рангам, а не по счёту: у кросс-энкодера шкала [0, 1], у MaxSim —
своя, несопоставимая. Складывать их напрямую нельзя.

**Замер 16 августа 2026 гибрид не оправдал** (298 задач `validation.jsonl`,
274 сопоставимых): b0 65.3 %, text 62.0 %, visual 60.8 %, hybrid 59.2 %.
Ни одно расхождение не значимо по МакНемару, но на задачах, где поиск дошёл
до ответа, гибрид отстал от b0 на 16.5 пункта — вдвое больше контекста
означает вдвое больше поводов отвлечься. Включать только с замером.

## Переменные

| переменная | по умолчанию | что делает |
|---|---|---|
| `MLA_RETRIEVAL_BACKEND` | `text` | `text`, `visual` или `hybrid` |
| `MLA_VISUAL_TRANSPORT` | `inprocess` | `inprocess` или `http` |
| `MLA_VISUAL_URL` | `http://127.0.0.1:8780` | адрес сервиса |
| `MLA_VISUAL_INDEX_DIR` | — | каталог индекса |
| `MLA_VISUAL_MIN_SCORE` | — | порог; без него бэкенд не стартует |
| `MLA_VISUAL_IMAGE_TOP_N` | `0` | сколько страниц картинкой в контекст |
| `MLA_PROMPT_VERSION` | `v2_cot` | политика тулы |

Задавайте их **в команде запуска**, а не в умолчаниях файлов: тогда
конфигурация записана в истории и не зависит от того, какая копия репозитория
где лежит.

## Три условия, без которых прогон отработает вхолостую

**Флаги tool-calling у vLLM.** `--enable-auto-tool-choice --tool-call-parser`.
Без них агент получает 400 на каждый запрос, прогон завершается, а числа
выглядят правдоподобно.

**Промпт-профиль `v2_cot_text_rag_v1`.** Дефолтная политика тулы написана
вокруг визуальных задач: единственный жёсткий триггер требует структурированного
визуального свидетельства. На текстовых бенчах он не срабатывает никогда — в
замере на TUMLU агент не вызвал поиск ни разу в 5693 задачах.

**Откалиброванный порог.** См. выше.

## Про картинку страницы

`MLA_VISUAL_IMAGE_TOP_N=1` подклеивает страницу в контекст отдельным
сообщением с явной подписью по-турецки, что это найденная страница, а не
условие задачи.

Без картинки визуальный ретрив вырождается: модель видит только `answer_text`,
то есть тот же OCR, что лежит в текстовом индексе. А там, где визуальный поиск
сильнее всего — схемы, формулы, плохие сканы, — `answer_text` как раз мусорный.

Одна, а не две: бюджет 16384 токена, картинка задачи уже занимает место, и
страница стоит ещё 1000–1600. Потеря места под `reasoning` однажды уже стоила
пайплайну 11 пунктов. Потолок считается на задачу, а не на вызов.

Картинка подклеивается только при вердикте `confident`.

## Что снимать

| таблица | как считается |
|---|---|
| общая точность | `python -m mla_baseline.eval --results <файл> --tasks <задачи>` |
| разрез по языкам | строки языки, колонки условия |
| годность прогона | `reasoning` заполнен, вызовов поиска на задачу, `exit_reason` |

Третью снимать обязательно: `reasoning` у 99 % и больше, ошибок меньше
процента, вызовы поиска не нулевые. Без неё первым двум верить нельзя.

Сравнивать `text` и `visual` только на одинаковых `task_id`.

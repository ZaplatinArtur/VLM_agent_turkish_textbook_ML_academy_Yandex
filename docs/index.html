01 · ПОСТАНОВКА

НЕ ПРОСТО ПОИСК.
РЕШЕНИЕ, КОГДА ИСКАТЬ.

Визуальное условие уже может содержать всё необходимое. Агент должен отличить недостаток знаний от задачи, где требуется только аккуратное рассуждение по изображению.

исследовательский вопрос

Улучшает ли текстовый, визуальный или гибридный поиск по учебникам качество ответов той же VLM-модели без инструментов?

↘
H1

Текст для точных знаний

Формулировки, определения и решения из учебной программы.

H2

Изображение для схем

Страница целиком сохраняет карты, графики и пространственные связи.

H3

Поиск может мешать

В самодостаточных задачах лишний контекст отвлекает от исходного условия.

H4

Нужна маршрутизация

Тип задачи должен определять: решать самому, искать текст или страницу.

02 · ПОДХОДЫ

ОДНА МОДЕЛЬ.
РАЗНЫЕ ИСТОЧНИКИ.

На одном наборе из 274 заданий меняется только источник контекста. Модель, формат ответа и оценка остаются одинаковыми.

B0

Модель видит только задание

Это честная точка отсчёта: текст, изображение и метаданные без внешних источников.

  • Источник: исходное изображение
  • Сильная сторона: нет шума retrieval
  • Риск: не хватает специфичных знаний
TEXT

Текст страницы после OCR

E5-small и BM25 объединяют кандидатов, затем дообученный кросс-энкодер повторно ранжирует их.

  • Единица: страница учебника
  • Порог: 0,5; слабая выдача скрывается
  • Риск: OCR теряет визуальные связи
VISUAL

Страница остаётся изображением

ColQwen ищет по визуальным токенам без OCR и передаёт найденную страницу агенту картинкой.

  • Источник: визуальный индекс страниц
  • Сильная сторона: схемы, карты и таблицы
  • Риск: порог уверенности плохо разделяет запросы
HYBRID

Обе ветки одновременно

Агент получает текстовые фрагменты и найденную страницу, чтобы объединить независимые сигналы.

  • Источник: текст и визуальная страница
  • Ожидание: взаимная компенсация ошибок
  • Результат: лишний контекст чаще отвлекал модель

✣
основной вывод

Гипотеза о среднем росте не подтвердилась: 65,3% без инструментов против 62,0% / 60,8% / 59,2% с поиском. Retrieval находит нужную страницу, но польза теряется из-за неполного покрытия корпуса, слишком частых вызовов и доверия к отвлекающему контексту. При этом отдельные предметы показывают, что правильный маршрут всё же может помочь.

# Проект и границы результата

## Задача

Проект решает школьные задания по изображениям и тексту на турецком языке. Модель должна не только выдать финальный ответ, но и работать с учебниками: определить тип задания, найти подходящую книгу и страницу, использовать условие, теорию или ключ ответа и не испортить сильный исходный ответ нерелевантным контекстом.

Практическая сложность состоит из четырёх частей:

1. изображение может содержать текст, формулу, таблицу, диаграмму или несколько связанных областей;
2. задача должна быть сопоставлена с конкретной книгой, редакцией, физической страницей и номером упражнения;
3. найденный фрагмент может быть похожим, но относиться к соседней задаче;
4. автоматический VLM-судья сам иногда ошибается, особенно на ответах-картинках.

## Benchmark-274

Все основные числа в этом комплекте относятся к одному зафиксированному development benchmark с SHA-256:

`5a6a38ccae7835f0d015f6e5979834208347b8e6e7a8d6884e4af97605f51ed9`

Состав:

| Срез | Количество |
|---|---:|
| Все задачи | 274 |
| Математика | 139 |
| Остальные предметы | 135 |
| Детерминированная оценка | 177 |
| Оценка по изображению / VLM judge | 97 |

Ошибки генерации и пустые ответы должны оставаться в знаменателе. Детерминированная и image-judge части не пересекаются и вместе покрывают все 274 строки.

## Главный инженерный вывод

Обычная схема `retrieval → контекст → новый ответ` оказалась недостаточно безопасной. Frozen page-RAG дал 141/274, а сильная модель без retrieval — 191/274. Значит, найденный контекст не должен автоматически получать право переписать ответ.

Финальный принцип:

> **RAG должен доказать право изменить ответ.**

Из этого следуют четыре архитектурных решения:

- reasoning-ответ сохраняется как anchor;
- источник ищется по наблюдаемому содержанию задачи, а не по benchmark ID;
- совпадение оформляется как проверяемый source certificate;
- при любой неоднозначности система fail-closed сохраняет anchor.

## Что дало рост

Рост получен не одним новым prompt и не обучением новой модели. Он состоит из последовательности системных улучшений:

1. сильный reasoning baseline вместо слабого always-on page-RAG;
2. асимметричный selector: хороший default меняется только при типизированном сигнале;
3. точная привязка к официальным PDF и ключам ответа;
4. предметные source adapters для разных форматов учебников;
5. визуальная привязка задания к странице через SIFT/RANSAC там, где текста недостаточно;
6. source-aware adjudication для строк, на которых прежний непрозрачный VLM judge противоречил точному официальному источнику.

## Текущий результат

### V6: наиболее чистый solver/source результат

- 238/274 = **0,868613**;
- математика: 112/139 = **0,805755**;
- non-math: 126/135 = **0,933333**;
- относительно V5 изменились ровно четыре ответа: три Biology и один Sociology;
- все четыре изменения были wrong → correct;
- код и source artifacts были заморожены до открытия score.

### V7: source-adjudicated system result

- 242/274 = **0,883212**;
- математика осталась 112/139 = **0,805755**;
- четыре изменения correctness относительно V6:
  - `val_0196`: новый solver answer, подтверждённый full-page fill-blank binding;
  - `val_0139`, `val_0141`, `val_0159`: ответ solver не изменился, но официальный сертификат исправил ошибочный verdict старого image judge.

Поэтому V7 — валидный результат нового source-adjudicated протокола, но не четырёхзадачное улучшение способности модели. Для сравнения чистой генерации правильнее показывать V6 отдельно.

## Сильная и слабая формулировка вклада

Сильная и честная:

> Мы построили evidence-gated multimodal QA pipeline, в котором ответ меняется только после exact-source binding и воспроизводимой проверки сертификата. Это сократило число ошибок на inspected development benchmark с 83 у no-tools baseline до 32 у V7, но переносимость на новые книги ещё должна быть проверена.

Слабая и рискованная:

> Мы создали революционный RAG с accuracy 88,3% и доказали его работу в production.

Вторая формулировка не выдержит вопросов про holdout, judge lineage и три evaluator corrections.

## Что остаётся недоказанным

- качество на book-disjoint unseen holdout;
- переносимость на русский, индонезийский и узбекский;
- location-independent clean-room replay;
- end-to-end latency именно V7, а не latency унаследованного anchor;
- устойчивость source adapters к новым редакциям и изменению верстки;
- статистическая неопределённость на новых книгах.

# Запуск и структура репозитория

## Важная граница текущего checkout

В текущем checkout репозитория находятся baseline agents, retrieval, judge, evaluation и UI. Полные source-native V6/V7 код и отчёты были собраны в отдельном рабочем дереве/ветке `feature/maxim-benchmark-results`. Поэтому этот runbook не притворяется, что команда `run-v7` уже доступна из любого чистого клона.

Для V6/V7 требуется отдельно восстановить pinned source branch, официальные PDF и runtime. Подробности — в [разделе о воспроизводимости](04_оценка_утечки_и_воспроизводимость.md).

## Основные каталоги

| Путь | Назначение |
|---|---|
| `src/mla_baseline` | запуск B0/B1/AgentRag, конфигурация, prompts, tools и tracing |
| `src/retrieve` | parsing/chunking/indexing и graph retrieval |
| `src/vlm_judge` | схемы, deterministic metrics, multimodal judge, aggregation и UI server |
| `scripts` | импорт учебников, построение индексов и исследовательские audit/eval scripts |
| `configs` | profiles и manifests |
| `data` | task JSONL, изображения и локальные входы; часть данных не хранится в Git |
| `artifacts` | corpus/index/cache/annotations и промежуточные outputs |
| `reports` | score reports и experiment manifests, если они присутствуют в checkout |
| `tests` | unit и integration tests; live Qwen tests запускаются отдельно |
| `docs/maxim_ru` | этот комплект документации |

## Установка

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[sources,dev]"
Copy-Item .env.example .env
```

Минимальная проверка:

```powershell
python -m pytest -q
```

Или совместимый с исходным README вариант:

```powershell
python -m unittest discover -s tests -v
```

Некоторые тесты требуют локальные artifacts или запущенный backend. Их нельзя молча считать regression failure обычной CPU-инсталляции; opt-in live tests должны запускаться отдельной командой и в отдельном отчёте.

## Настройка backend

Основные поля `.env`:

```dotenv
MLA_VLLM_BASE_URL=http://localhost:8000/v1
MLA_VLLM_API_KEY=EMPTY
MLA_MODEL_NAME=Qwen/Qwen3.5-9B
MLA_MAX_TOKENS=3072
MLA_TEMPERATURE=0.0
MLA_ENABLE_THINKING=false
MLA_PROMPT_VERSION=v1
MLA_STRUCTURED_MODE=response_format
MLA_CONCURRENCY=4
MLA_DATA_ROOT=data
MLA_RESULTS_DIR=results
```

Для сравнимого benchmark run модель, checkpoint, chat template, prompt, thinking flag, max tokens и decoding settings должны быть записаны в resolved manifest. Простого имени модели недостаточно.

## Smoke test без модели

Dry-run проверяет task schema, изображения и сборку request, но не качество модели:

```powershell
python -m mla_baseline.runner `
  --tasks data/tasks.sample.jsonl `
  --condition b0_no_tools `
  --limit 2 `
  --dry-run
```

Если в задаче есть image placeholder, а `MLA_TEXT_ONLY=true`, preflight должен завершить run ошибкой до вызова backend. Это полезная fail-fast защита от нечестного text-only запуска визуального benchmark.

## Запуск Qwen через vLLM

Пример профиля для GPU-машины:

```bash
vllm serve Qwen/Qwen3.5-9B \
  --max-model-len 16384 \
  --gpu-memory-utilization 0.92 \
  --max-num-seqs 32 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder
```

Проверка endpoint:

```bash
curl http://localhost:8000/v1/models
```

На общем сервере число replicas, `max-num-seqs` и concurrency надо выбирать по согласованному resource window. Документация не предполагает вытеснение чужих процессов.

## Запуск baseline

Сначала короткий smoke:

```powershell
python -m mla_baseline.runner `
  --tasks data/tasks.sample.jsonl `
  --condition b0_no_tools `
  --limit 2 `
  --out results/b0_smoke.jsonl
```

Затем полный запуск:

```powershell
python -m mla_baseline.runner `
  --tasks data/validation.jsonl `
  --condition b0_no_tools `
  --out results/b0_no_tools.jsonl `
  --report `
  --meta data/validation.meta.jsonl
```

Runner продолжает существующий output по `task_id`. Для повторения только ошибочных строк используется `--retry-errors`. Для независимого нового эксперимента надо выбирать новый output path, а не перезаписывать исходный artifact.

Доступные `condition` определяются registry в `mla_baseline.runner`; среди основных веток находятся `b0_no_tools`, web/deep варианты и `agent_rag`.

## Textbook retrieval baseline

### Подготовка corpus и BM25

```powershell
vlm-judge prepare-corpus `
  --input odevjet.jsonl `
  --output-dir artifacts/corpus `
  --max-chars 1600 `
  --overlap-chars 200

vlm-judge build-bm25 `
  --chunks artifacts/corpus/chunks.jsonl `
  --index artifacts/retrieval/bm25.sqlite

vlm-judge serve-retrieval `
  --index artifacts/retrieval/bm25.sqlite `
  --port 8770
```

Пример retrieval settings:

```dotenv
MLA_RETRIEVAL_BASE_URL=http://127.0.0.1:8770
MLA_RETRIEVAL_TOP_K=5
MLA_RETRIEVAL_MAX_CONTEXT_CHARS=6000
MLA_RETRIEVAL_MAX_CALLS=3
MLA_RETRIEVAL_RELAX_GRADE=false
```

### Оценка retrieval отдельно от QA

```powershell
vlm-judge prepare-retrieval-qrels `
  --benchmark artifacts/math_benchmark.jsonl `
  --output artifacts/retrieval/math_qrels_template.jsonl

vlm-judge evaluate-retrieval `
  --index artifacts/retrieval/bm25.sqlite `
  --qrels artifacts/retrieval/math_qrels.jsonl `
  --k 1 --k 5 --k 10 `
  --output artifacts/reports/bm25_eval.json
```

Retrieval Recall@k и answer accuracy — разные метрики. Ранний element proxy хорошо локализовал упражнения, но ухудшал конечный ответ; их нельзя смешивать.

## Judge и full-denominator evaluation

### Детерминированная часть

```powershell
vlm-judge import-candidates `
  --benchmark artifacts/math_benchmark.jsonl `
  --responses results/b0_no_tools.jsonl `
  --setup no_tools `
  --output artifacts/runs/no_tools.jsonl

vlm-judge score-deterministic `
  --input artifacts/runs/no_tools.jsonl `
  --output artifacts/runs/no_tools_exact.jsonl
```

### Подготовка и запуск blind judge

```powershell
vlm-judge prepare-requests `
  --input artifacts/runs/no_tools.jsonl `
  --output artifacts/runs/no_tools_requests.jsonl

vlm-judge run-judge `
  --input artifacts/runs/no_tools_with_gold.jsonl `
  --output artifacts/runs/no_tools_judged.jsonl `
  --base-url http://127.0.0.1:18001/v1 `
  --model Qwen/Qwen3.5-9B `
  --disable-thinking
```

Setup label не должен попадать в prompt судьи. Candidate answer и reasoning передаются раздельно. Judge failure и solver failure нельзя удалять из denominator.

### Aggregation

```powershell
vlm-judge aggregate `
  --input artifacts/runs/scored_records.jsonl `
  --output artifacts/reports/summary.json
```

В отчёте следует показывать deterministic и image-judge slices отдельно, а также coverage, failures и paired changes.

## Интерфейс разметки и adjudication

```powershell
vlm-judge-ui `
  --dataset artifacts/calibration/response_sample.jsonl `
  --annotations artifacts/annotations/human.jsonl `
  --gold artifacts/annotations/gold.jsonl `
  --judge-results artifacts/runs/judge_results.jsonl `
  --adjudications artifacts/annotations/adjudications.jsonl `
  --open-browser
```

UI должен использоваться для независимой оценки до показа verdict модели. После первичной метки можно открывать режим adjudication и разбирать disagreement.

## Как проверять один experiment artifact

Минимальный manifest должен содержать:

- experiment ID и human-readable label;
- commit и dirty-tree status;
- task set SHA и task order SHA;
- model/checkpoint/prompt/decoding settings;
- source index и PDF hashes;
- solver output SHA;
- judge/scorer hashes;
- число входов, успехов, failures и missing;
- точную команду и время запуска.

Проверка перед score:

```powershell
Get-FileHash data/validation.jsonl -Algorithm SHA256
Get-FileHash results/candidate.jsonl -Algorithm SHA256
git rev-parse HEAD
git status --short
```

Dirty tree не делает run автоматически невалидным, но diff обязан быть сохранён и привязан к manifest. Для заявленного one-shot лучше использовать clean commit.

## Восстановление source-native V6/V7

Исторические primary artifacts указывают на:

- branch `feature/maxim-benchmark-results`;
- V6 commit `c8c93f3ecdf019e5534a132b20d2320dbe6269bf`;
- V7 launch commit `9e6bcaac01c48c7758396aa7fed543dafd3bd02b`;
- внешние official PDFs с pinned SHA;
- pinned Python/OpenCV/NumPy/Poppler runtime.

Перед попыткой replay надо проверить наличие branch/commits в remote и получить разрешённые source bytes. Нельзя заменять недоступный PDF «похожей» новой версией и считать hashes эквивалентными.

Пока это не упаковано в hermetic manifest/container, корректная процедура — следовать pre-score handoff конкретной версии, а не придумывать универсальную команду из документации.

## Безопасный порядок нового измерения

1. Проверить schema и images dry-run.
2. Запустить 2–5 задач на настоящем backend.
3. Зафиксировать resolved config и hashes.
4. Выполнить generation в новый output path.
5. Проверить полноту task grid.
6. Закрыть generation artifact для записи.
7. Только затем подключить references/judge.
8. Посчитать full-denominator score один раз.
9. Сохранить report и paired changes.
10. После score не ретюнить тот же заявленный run.

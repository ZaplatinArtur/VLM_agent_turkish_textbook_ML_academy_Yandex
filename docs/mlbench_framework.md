# Мультиязычный бенч-фреймворк: как гонять свои условия

Готовый конвейер «скачать бенчмарк → зафиксировать срез → прогнать любое наше
условие → посчитать сводку». Всё в Task-контракте, поэтому работает с любым
солвером из `mla_baseline.solvers` (B0, b1_*, agent_rag_*) без правок кода —
и с любым будущим, который держит контракт.

## Из чего состоит

| Кусок | Что делает |
|---|---|
| `scripts/fetch_mlbench.py` | реестр бенчмарков + скачивание с HF + конвертация в Task-JSONL; картинки сами ужимаются до 1600px |
| `scripts/make_bench300.py` | детерминированный срез (сид 47, стратификация по предмету) — **канон, уже зафиксирован в `data/mlbench/bench300/`** |
| `scripts/stand/make_joblist.py` | генерирует список работ «бенчмарк × язык × условие» |
| `scripts/stand/worker.sh` | воркер: разбирает joblist через mkdir-локи, по воркеру на GPU/порт |
| `scripts/stand/grab_watcher.sh` | ждёт освобождения карт и сам поднимает vLLM + воркера |
| `scripts/score_mlbench.py` | текстовая сводка: языки × условия, предметы, тул-цикл, здоровье прогонов |
| `scripts/build_dashboard.py` | интерактивный HTML-отчёт: разбивки по языкам, предметам, типу вопроса и модальности, фильтры и графики в одном файле |

## Что уже скачано и заморожено

- **TUMLU** — 9 тюркских языков, школьные MCQA от носителей (канон-300: 2615).
- **EXAMS-V** — 13 языков, вопрос = скриншот экзамена (канон-300: 3149).
- **MGSM** — 11 языков, 250 открытых числовых матзадач (перевод вручную).

Все ответы меряются точным совпадением — судья не нужен. Канон-300 менять
нельзя: на нём уже сняты базовые цифры (см. `reports/mlbench300_summary.md`);
новые условия сравнивайте с ними на тех же задачах.

## Быстрый старт на стенде

```bash
# 1) окружение как в memory (vLLM 0.17 + torch 2.10 cu128 для V100), данные:
scp -r data/mlbench <стенд>:~/<папка>/data/
scp scripts/stand/* <стенд>:~/<папка>/

# 2) сервер(ы) — на СВОЕЙ карте, util 0.85 (0.90 падает в OOM на картинках):
CUDA_VISIBLE_DEVICES=<gpu> setsid nohup .venv/bin/python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3.5-9B --port 8010 --max-model-len 32768 --dtype float16 \
  --gpu-memory-utilization 0.85 --reasoning-parser qwen3 \
  --enable-auto-tool-choice --tool-call-parser qwen3_xml > vllm.log 2>&1 &

# 3) очередь и воркер (по одному на карту, порты разные):
python make_joblist.py --benches tumlu --conditions b0_no_tools,ваше_условие > joblist.txt
PORT=8010 setsid nohup ./worker.sh > worker_8010.log 2>&1 &

# 4) сводка (локально, скачав results/):
python scripts/score_mlbench.py --results <каталог с результатами>

# 5) интерактивный отчёт — один самодостаточный HTML, открывается без сервера:
python scripts/build_dashboard.py --conditions b0,<ваше_условие>
```

Дашборд считает то же, что и скорер, но даёт разрезы: язык, предмет, закрытый
или открытый вопрос, текст или скриншот, искал агент или нет. Вёрстка и графики
живут в `reports/dashboard_template.html`, скрипт только подставляет данные.

Прогон возобновляемый: воркер пропускает работы, где выход полон, и продолжает
частичные. Локи в `locks/` — перед перезапуском после сбоя снять локи
незавершённых работ (grab_watcher делает это сам).

## Грабли, уже собранные за вас

1. **Пути картинок** — относительно `data_root` (`mlbench/...`), БЕЗ префикса
   `data/`: солвер добавляет его сам.
2. **Картинки >2 Мп** на V100 = таймауты 900с; fetch теперь ужимает сам, но
   если приносите свой датасет — ужимайте до 1600px.
3. **`--tool-call-parser qwen3_xml`**, не hermes: hermes молча теряет вызовы,
   и условие с поиском «не ищет».
4. **`--reasoning-parser qwen3`** обязателен, иначе структурный вывод душит
   размышление (−11 пп и хуже).
5. **pkill/pgrep по подстроке** на общем стенде — не делайте: паттерн ловит
   ваши же ssh-обёртки. Только якорные шаблоны (`^/bin/bash [.]/worker`).
6. Разница условий **меньше ~5 пп в одиночном прогоне — шум** (калибровка в
   `reports/tool_errors_analysis.md`). Для выводов — мульти-прогон.
7. **Алфавит буквы-ответа.** Болгарские экзамены нумеруют варианты
   кириллицей (А/Б/В/Г), модель отвечает латиницей позиционно — сырое
   сравнение даёт 23% вместо 93%. Скорер нормализует по позиции
   (`_norm_choice`); для новых языков с нелатинскими буквами вариантов
   проверяйте распределение ответов, прежде чем верить цифре.

## Базовые цифры для сравнения (Qwen3.5-9B, V100, канон-300)

- TUMLU B0: турецкий 86.3% → каракалпакский 62.0%; b1_search: Δ −3..+4 (шум).
  Математика/физика 85–98% на всех языках; проседает языково-культурное.
- MGSM B0: 80–95%; b1_search в минусе на **всех 11 языках**, среднее −6.3 пп —
  на открытой математике поиск строго вреден, роутинг обязателен.
- EXAMS-V B0: 62–100% (медиана ~90%); b1_search: медианное Δ −1.4 (шум).
  Скриншоты после ужатия модель читает уверенно; слабые места — польский
  (65%) и университетская английская часть (84%).

Полные таблицы: `reports/mlbench300_summary.md`.

Сырые результаты прогонов — `reports/mlbench300/` и `reports/mgsm/` в этой
ветке; каждый файл — стандартный SolveResult-JSONL, совместимый с судьёй и
HTML-отчётами.
